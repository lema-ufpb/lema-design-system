# LEMA-DS <small className="text-muted-foreground text-base font-normal">v{VERSION}</small> 🚀

_Design system oficial do LEMA/UFPB — acessível, temático e pronto para produção._

**LEMA-DS** é o design system e a biblioteca de componentes oficiais do [Laboratório de Economia e Modelagem Aplicada (LEMA)](https://lema.ufpb.br), na Universidade Federal da Paraíba (UFPB). Ele existe para dar às equipes do laboratório — e a qualquer projeto que queira adotá-lo — uma base sólida de componentes React, acessíveis e temáticos, construída sobre o shadcn/ui e as primitivas do Radix UI.

Sob o capô, o LEMA-DS é construído com [React 19](https://react.dev/) e [Next.js 16](https://nextjs.org/), com tipagem de ponta a ponta garantida pelo [TypeScript](https://www.typescriptlang.org/). A estilização é inteiramente [Tailwind CSS v4](https://tailwindcss.com/) — via `@theme inline`, sem `tailwind.config.js` — construída sobre as primitivas acessíveis do [Radix UI](https://www.radix-ui.com/) e a camada base do [shadcn/ui](https://ui.shadcn.com/) (`components/ui`, 61 primitivos, nunca editados manualmente). As variantes de cada componente são tipadas com [class-variance-authority](https://cva.style/), sempre com `defaultVariants` definidos. E tudo isso é documentado e testado aqui mesmo, neste [Storybook 10](https://storybook.js.org/), com [Vitest](https://vitest.dev/) rodando em modo browser via `make test`.

A biblioteca é organizada em três camadas que se apoiam umas nas outras — da fundação de tokens até os blocos prontos para montar uma página inteira.

A primeira camada é a **fundação**: o "DNA" do design system. São os tokens semânticos de cor (`--background`, `--foreground`, `--primary`, `--muted`, `--border`, cada um com seu par para o modo escuro), a escala de risco (`--risk-1` a `--risk-4`) usada em visualização de dados, e os tokens de destaque e gráficos (`--highlight-violet/sky/white`, `--chart-1` a `--chart-5`) — sempre tokens, nunca hex cru. O suporte a temas claro, escuro e sistema vem do `ToggleTheme` com `next-themes`, e a internacionalização é centralizada em `lib/ui-i18n.ts`: quatro idiomas prontos de fábrica, e basta passar a prop `locale` para que a dependência `ui-i18n` seja instalada automaticamente.

A segunda camada são os **primitivos shadcn/ui**: 61 componentes atômicos e acessíveis vivendo em `components/ui/`, a base literal de tudo o que vem depois. Eles nunca são editados manualmente — qualquer ajuste ali se perde na próxima atualização — então toda mudança passa pelo CLI oficial, `npx shadcn@latest add <componente> --yes`. É onde moram os alicerces de formulário ([Button](/docs/shadcn-ui-button--docs), [Input](/docs/shadcn-ui-input--docs), [Field](/docs/shadcn-ui-field--docs)…), as sobreposições ([Dialog](/docs/shadcn-ui-dialog--docs), [Drawer](/docs/shadcn-ui-drawer--docs), [Sheet](/docs/shadcn-ui-sheet--docs)…), a exibição de dados ([Card](/docs/shadcn-ui-card--docs), [Table](/docs/shadcn-ui-table--docs), [Avatar](/docs/shadcn-ui-avatar--docs)…) e até uma família inteira de chat ([Bubble](/docs/shadcn-ui-bubble--docs), [Message](/docs/shadcn-ui-message--docs), [MessageScroller](/docs/shadcn-ui-messagescroller--docs)).

A terceira camada é onde o design system ganha personalidade: os **componentes LEMA-DS**. São 275 composições em `components/ds/`, mais quatro bibliotecas compartilhadas (`lib/ui-i18n.ts`, `lib/format-utils.ts`, `lib/chart-axis-width.ts`, `lib/card-stats-shared.tsx`). Cada uma entra no `registry.json` com o prefixo `ds-` e é instalável com `npx shadcn@latest add ds-<nome>` — o arquivo cai direto em `components/ui/ds-<nome>.tsx`, sem colidir com o primitivo que estende. Como este é um design system spec-first, cada componente também carrega sua spec em `docs/specs/ds-<nome>.md` e sua história (`.stories.tsx`) lado a lado no código.

Duas portas de entrada, o mesmo registry por trás.

### Via `@lema-ufpb/ds-sync` (recomendado para projetos da UFPB)

O `ds-sync` é o caminho mais direto para projetos internos: instala, verifica drift e sincroniza tudo de uma vez, deixando um `components.lock` versionado no repositório.

```bash
npm install -D @lema-ufpb/ds-sync
```

```bash
npx ds add dashbox bar-chart
npx ds add ds-tilt-card ds-spotlight-card
npx ds verify
npx ds sync --all --yes
```

> `components.lock` deve ser commitado junto com o código.

### Via CLI do shadcn

Prefere o caminho padrão do ecossistema shadcn? Funciona igual, componente a componente:

```bash
npx shadcn@latest add ds-card-stat
npx shadcn@latest add ds-hero-layers
npx shadcn@latest add ds-dashboard
```

> `lib/ui-i18n.ts` é instalado automaticamente como dependência `registry:lib` sempre que um componente com suporte a idiomas entra no projeto.


`locale` assume `en-US` por padrão. Para adicionar um novo idioma, basta estender `UI_I18N`.

Acessibilidade não é opcional aqui: cada componente segue as diretrizes WAI-ARIA, responde à navegação por teclado, respeita `prefers-reduced-motion` e passa por checagens `axe` diretamente no Vitest, seguindo WCAG 2.1 AA. Os temas claro, escuro e "sistema" funcionam inteiramente por tokens semânticos (`bg-primary`, `text-muted-foreground`, `bg-success`, `bg-risk-1`…`4`, `bg-muted`) — nenhuma sobrescrita manual de `dark:` em lugar nenhum do código. O layout é mobile-first, com `@container` queries e um `SidebarProvider` que se adapta à tela. A tipagem é 100% TypeScript, com `VariantProps` cobrindo cada variante do CVA. E como o design system é spec-first, os 320 arquivos de spec em `docs/specs/` acompanham lado a lado os componentes de `components/ds/`, cada um com sua própria história de Storybook.
