# LEMA-DS <small className="text-muted-foreground text-base font-normal">v{VERSION}</small> 🚀

_Official design system of LEMA/UFPB — accessible, themeable, and production-ready._

**LEMA-DS** is the official design system and component library of the [Laboratory of Economics and Applied Modeling (LEMA)](https://lema.ufpb.br) at the Federal University of Paraíba (UFPB). It exists to give the lab's teams — and any project that wants to adopt it — a solid foundation of accessible, themeable React components, built on top of shadcn/ui and Radix UI primitives.

Under the hood, LEMA-DS is built with [React 19](https://react.dev/) and [Next.js 16](https://nextjs.org/), with end-to-end type safety guaranteed by [TypeScript](https://www.typescriptlang.org/). Styling is entirely [Tailwind CSS v4](https://tailwindcss.com/) — via `@theme inline`, without `tailwind.config.js` — built on top of the accessible [Radix UI](https://www.radix-ui.com/) primitives and the [shadcn/ui](https://ui.shadcn.com/) base layer (`components/ui`, 62 primitives, never edited manually). Each component's variants are typed with [class-variance-authority](https://cva.style/), always with `defaultVariants` defined. And everything is documented and tested right here, in this [Storybook 10](https://storybook.js.org/), with [Vitest](https://vitest.dev/) running in browser mode via `make test`.

The library is organized into three layers that build on each other — from token foundations to ready-to-assemble page blocks.

The first layer is the **foundation**: the design system's "DNA". These are the semantic color tokens (`--background`, `--foreground`, `--primary`, `--muted`, `--border`, each with its dark-mode counterpart), the risk scale (`--risk-1` to `--risk-4`) used in data visualization, and the highlight and chart tokens (`--highlight-violet/sky/white`, `--chart-1` to `--chart-5`) — always tokens, never raw hex. Light, dark, and system theme support comes from `ToggleTheme` with `next-themes`, and internationalization is centralized in `lib/ui-i18n.ts`: four languages out of the box, and just pass the `locale` prop for the `ui-i18n` dependency to be installed automatically.

The second layer is the **shadcn/ui primitives**: 62 atomic, accessible components living in `components/ui/`, the literal foundation of everything that comes after. They are never edited manually — any change there would be lost on the next update — so every change goes through the official CLI, `npx shadcn@latest add <component> --yes`. This is where form foundations live ([Button](/docs/shadcn-ui-button--docs), [Input](/docs/shadcn-ui-input--docs), [Field](/docs/shadcn-ui-field--docs)…), overlays ([Dialog](/docs/shadcn-ui-dialog--docs), [Drawer](/docs/shadcn-ui-drawer--docs), [Sheet](/docs/shadcn-ui-sheet--docs)…), data display ([Card](/docs/shadcn-ui-card--docs), [Table](/docs/shadcn-ui-table--docs), [Avatar](/docs/shadcn-ui-avatar--docs)…) and even a whole chat family ([Bubble](/docs/shadcn-ui-bubble--docs), [Message](/docs/shadcn-ui-message--docs), [MessageScroller](/docs/shadcn-ui-messagescroller--docs)).

The third layer is where the design system gains personality: the **LEMA-DS components**. There are 308 compositions in `components/ds/`, plus four shared libraries (`lib/ui-i18n.ts`, `lib/format-utils.ts`, `lib/chart-axis-width.ts`, `lib/card-stats-shared.tsx`). Each enters `registry.json` with the `ds-` prefix and is installable with `npx shadcn@latest add ds-<name>` — the file lands directly in `components/ui/ds-<name>.tsx`, without colliding with the primitive it extends. As this is a spec-first design system, each component also carries its spec in `docs/specs/ds-<name>.md` and its story (`.stories.tsx`) side-by-side in code.

  <h2>Installing components</h2>
</div>

Two entry points, same registry behind it.

### Via `@lema-ufpb/ds-sync` (recommended for UFPB projects)

The `ds-sync` is the most direct path for internal projects: it installs, checks drift and syncs everything at once, leaving a versioned `components.lock` in the repository.

```bash
npm install -D @lema-ufpb/ds-sync
```

```bash
npx ds add dashbox bar-chart
npx ds add ds-tilt-card ds-spotlight-card
npx ds verify
npx ds sync --all --yes
```

> `components.lock` should be committed alongside code.

### Via shadcn CLI

Prefer the standard shadcn ecosystem path? It works the same, component by component:

```bash
npx shadcn@latest add ds-card-stat
npx shadcn@latest add ds-hero-layers
npx shadcn@latest add ds-dashboard
```

> `lib/ui-i18n.ts` is automatically installed as a `registry:lib` dependency whenever a component with language support enters the project.

Accessibility is not optional here: every component follows WAI-ARIA guidelines, responds to keyboard navigation, respects `prefers-reduced-motion` and passes `axe` checks directly in Vitest, following WCAG 2.1 AA. Light, dark and "system" themes work entirely through semantic tokens (`bg-primary`, `text-muted-foreground`, `bg-success`, `bg-risk-1`…`4`, `bg-muted`) — no manual `dark:` overrides anywhere in the code. Layout is mobile-first, with `@container` queries and a `SidebarProvider` that adapts to the screen. Typing is 100% TypeScript, with `VariantProps` covering every CVA variant. And as the design system is spec-first, the 368 spec files in `docs/specs/` sit alongside the `components/ds/` components, each with its own Storybook story.
